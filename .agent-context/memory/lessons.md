- **[backend/auth]** Default auth mode is `DASHBOARD_AUTH=none` (`config.go` default) → `BypassAuth=true` → `RequireAuth` middleware is **skipped**, so **no JWT payload is ever placed in the request context**. Handlers must NOT re-gate on `auth.PayloadFromContext()` and 403 when absent — that breaks every route in the default (bypass) config. Auth is enforced at the middleware layer only; handlers trust it (`payload, _ :=`, never `if !ok { 403 }`). The refine handlers (`api/refine/handler.go`) had this bug → all 3 routes 403'd in bypass mode. Fixed across the board (2026-05-30): refine + wphandler dropped the dead guards (payload discarded); `search`/`remotes`/`history` substitute `auth.BypassPayload()` (SSOT helper in `internal/auth/jwt.go`, `Sub="local"`/`IsAdmin=true`, matching `/api/me` via `auth.BypassUserID`) on `!ok` instead of 403 — needed because they key per-user data on `payload.Sub`. `presets` was already correct (`if ok { userID=&Sub }` → nil = global in bypass; deliberately left). **Invariant making the substitution safe:** `!ok` can ONLY occur in bypass mode — RequireAuth 401s unauthenticated requests before any handler runs in auth mode — and all these handlers are mounted inside the protected `r.Group`, so the local-admin fallback can never grant an unauthenticated request access. **Regression guard:** `server/internal/api/bypass_auth_smoke_test.go` (`TestBypassAuth_NoProtectedRouteReturnsAuthError`) builds the full production router in `BypassAuth=true` against in-memory SQLite, `chi.Walk`s EVERY registered route, fires an unauthenticated request (loopback Host + matching Origin), and asserts none return 401/403 except an explicit `bypassSkip` allow-list (OAuth dance, bearer-auth ingress `/api/hooks/event|pre-tool` + `/api/mcp` + `/api/channel-reply`, SSE streams, `DELETE /api/me`). New routes are covered automatically. NOTE: the test sets a huge `AuthRateLimiterConfig` — without it the per-IP limiter (burst 20) 429s the 100+ rapid requests and masks the 401/403. When adding a new bearer-token route OUTSIDE the JWT group, add it to `bypassSkip`. `conf:high` (2026-05-30)
- **[backend/hooks]** `/api/hooks/*` has **two consumer classes with different auth**: hook-script ingress (`event`, `pre-tool`) carries `DASHBOARD_HOOKS_SECRET` (bearer) and mounts OUTSIDE the JWT group; the edit-gate UI (`pending` GET, `respond` POST) is called by the **browser** (`EditGateModal.vue`) with the session cookie, so it must mount INSIDE the protected JWT group and must NOT call `requireSecret` — otherwise the browser gets 401. - **[git/danger]** NEVER run `git stash` followed by `git stash pop` to "temporarily" shelve changes when the working tree might be clean. `git stash` on a clean tree saves NOTHING ("No local changes to save"), so the subsequent `git stash pop` applies an unrelated OLD stash from the stack (this repo has 38+ leftover stashes) onto your tree — instant merge conflicts in random files. Happened 2026-05-30: a speculative stash/pop around a `git show` applied `refactor/unify-audit-events: follow-up agent leftovers` and conflicted di.go/handler.go/client.go. - **[git/gone-branch-cleanup]** Cleaning `[gone]`-upstream branches + worktrees: the `clean_gone` skill's blind `git branch -vv | grep '\[gone\]'` script has two traps in this repo. (1) **Squash-merge breaks ancestry** — merged PRs re-write history, so `git merge-base --is-ancestor <branch> origin/main` reports merged branches as UNMERGED.
